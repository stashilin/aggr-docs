title: "Создать депозит"
description: "Заводит заявку на приём платежа и возвращает её ключ — transaction_id."
openapi: "/api-reference/openapi.yaml POST /v1/deposits"
---

Первый шаг пути заявки. Вы сообщаете, сколько ждёте и каким способом клиент будет платить, — в ответ получаете `transaction_id`, ключ, по которому дальше живёт вся заявка.

Ответ на этот вызов одинаков для обоих вариантов интеграции и **не содержит ни реквизитов, ни ссылки на оплату**: их ещё нет, платёжная система подбирается уже после создания. За ними нужно прийти в [«Статус депозита»](/api-reference/operations/status) — как это выглядит по шагам, показано в [Пути заявки](/scenarios-payment).

Чем h2h отличается от redirect и какой выбрать — в разделе [Как это работает](/index). Успешный ответ здесь означает «заявка заведена», а не «деньги получены»: отказ по самому запросу и неуспех заявки — разные вещи, см. [Что может пойти не так](/failures).
