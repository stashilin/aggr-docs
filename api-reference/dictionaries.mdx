## Главное правило

`method`, `bank` и `traffic_type` передаются отдельными полями:

- `method` определяет механику перевода;
- `bank` определяет выбранный пользователем банк;
- `traffic_type` передаёт уровень пользователя в вашей системе и не зависит от метода или банка;
- название банка не зашивается в произвольный код метода;
- `sber_qr` и `vtb_qr` — два утверждённых исключения, где банк определяет сам QR-контур;
- если `bank` не передан, его выбирает Сервис;
- если `traffic_type` не передан, маршрут строится без фильтра по типу трафика.

<Warning>
  Не составляйте значения вроде `sber_sbp` или `tbank_c2c`. Передавайте
  `method: sbp` и `bank: sber` как два отдельных параметра. Используйте
  `sber_qr` и `vtb_qr` только как готовые значения справочника — не создавайте
  другие комбинации самостоятельно.
</Warning>

```json
{
  "method": "sbp",
  "bank": "sber",
  "traffic_type": "ftd"
}
```

## Платёжные методы

| Код | Название | Описание |
| --- | --- | --- |
| `sbp` | СБП | Перевод по номеру телефона через Систему быстрых платежей |
| `c2c` | Перевод на карту | Перевод по номеру банковской карты |
| `nspk` | QR НСПК | Оплата по QR-коду или платёжной ссылке НСПК |
| `sber_qr` | QR Сбербанка | Оплата по QR-коду или платёжной ссылке Сбербанка; формат реквизитов как у `nspk` |
| `vtb_qr` | QR ВТБ | Оплата по QR-коду или платёжной ссылке ВТБ; формат реквизитов как у `nspk` |
| `transgran` | Трансграничный перевод | Перевод на иностранные реквизиты по выданной инструкции |
| `sim_transgran` | Трансграничный перевод через SIM-карту | Перевод на SIM-карту или мобильный номер; валюта и инструкция как у `transgran` |
| `sim` | Мобильная коммерция | Оплата с баланса SIM-карты или мобильного номера |

Список может расширяться совместимо с v1. Неизвестный или недоступный метод вернёт
ошибку запроса; депозит при этом не создаётся.

## Тип трафика

`traffic_type` — необязательный уровень пользователя в системе клиента на момент создания
депозита. Классификацию определяет и передаёт клиент; Сервис принимает значение как есть,
не вычисляет его по собственной истории и использует при выборе подходящего маршрута.

| Код | Значение |
| --- | --- |
| `ftd` | Первый депозит по классификации системы клиента |
| `std` | Повторный депозит по классификации системы клиента |

Если поле отсутствует, уровень пользователя считается неуказанным и маршрут строится без
фильтра по типу трафика.

## Состав реквизитов

В H2H реквизиты приходят в `GET /v1/deposits/{transaction_id}` после их выдачи.

| Метод | Поля реквизитов | Особенность |
| --- | --- | --- |
| `sbp` | `phone`, `bank`, `bank_name`, `recipient_name` | Перевод по телефону |
| `c2c` | `card_number`, `bank`, `bank_name`, `recipient_name` | Перевод по номеру карты |
| `nspk` | `payment_url`, `qr_data`, `qr_image_url` | QR или платёжная ссылка НСПК |
| `sber_qr` | `payment_url`, `qr_data`, `qr_image_url` | Та же форма ответа, что у `nspk`, для QR Сбербанка |
| `vtb_qr` | `payment_url`, `qr_data`, `qr_image_url` | Та же форма ответа, что у `nspk`, для QR ВТБ |
| `transgran` | `card_number` или `phone`, `bank_name`, `payment_currency`, `instruction` | Всегда показывайте клиенту `instruction` целиком |
| `sim_transgran` | `phone`, `bank_name`, `payment_currency`, `instruction` | Как `transgran`, но получатель — SIM-карта или мобильный номер |
| `sim` | `phone`, `instruction` | Оплата с баланса SIM-карты или мобильного номера |

вернёт `400 BANK_NOT_SUPPORTED_FOR_METHOD`. Если код банка неизвестен —
`400 BANK_UNKNOWN`.

## Как передавать банк

Передавайте `bank`, когда клиент уже выбрал банк в вашем интерфейсе. Сервис постарается
выдать реквизиты в этом банке, чтобы перевод прошёл внутри банка. Если выбор банка клиенту
не показывается, поле можно не передавать — маршрут выберет Сервис.
