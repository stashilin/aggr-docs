# План качественных флоу портала

Служебный документ. В навигацию `docs.json` НЕ добавлять.
Основание: карты болевых точек двух аналитиков (зоны «деньги и состояния» и «интеграционный
контур»), отчёты прошлой ревизии (journal `wf_5f41ad8b-dfb`), спека
`aggr-contract/contract/openapi.yaml`, портал `aggr-docs/*.mdx` по состоянию на 2026-08-04.

## 0. Принципы (требования владельца)

1. **Аудитория — аналитики.** Ноль JSON, ноль curl, ноль HTTP-кодов на страницах вкладки
   «Документация». Словари `status`/`stage` разрешены. Механика живёт в API Reference.
2. **Одна боль — один хозяин.** У каждой боли ровно одна страница-хозяин, где она раскрыта
   полностью; остальные страницы ссылаются, не пересказывают (сателлит — максимум два
   предложения + ссылка).
3. **Парадные схемы — красиво, рабочие — Mermaid.** Бюджет парадных: **2 обязательные + 1
   резервная** на весь портал. Парадная = отрисованная статичная иллюстрация (светлая и тёмная
   версии в `/images`, исходник в `_design/`). Всё остальное — Mermaid в тексте страницы.
4. **Поля — через Field/Tree.** Каждое поле: имя → тип словами → суть одной фразой → **что
   значит отсутствие** (или присутствие — для блоков). Реализация: Mintlify `ResponseField`
   (+ `Expandable` для вложенности), тип по-русски («сумма», «момент времени», «словарь»).
5. Правки спеки — отдельная волна (раздел 5): портал не чинит спеку, но план фиксирует обе
   стороны, чтобы факт жил в одном месте.

Контекст из прошлой ревизии: Mintlify не рендерит `info.description` спеки — поэтому разделы
«Лимиты», «Версионирование», «Трассировка и поддержка», «Общие принципы и форматы» выпали из
портала. Частично уже закрыто новыми страницами `api-reference/{authentication,conventions,
sandbox-reference}.mdx`; остаток закрывается разделом 4 этого плана.

## 2. Детальные задания по болям

### Д1 · Три суммы (хозяин `amounts.mdx`) — критичная

Страница уже лучшая на портале; довести, не переписывать.

1. Таблицу «поле → вопрос → когда появляется» (`amounts.mdx:9–13`) перевести в Field/Tree:
   - `amount` — тип «сумма» — «сколько просили заплатить» — *отсутствовать не может*;
   - `pay_amount` — тип «сумма» — «сколько назначено заплатить фактически» — **«Если поля
     нет: назначенная сумма совпадает с `amount` — сверяйте по нему»** (эта строка — ядро
     боли, правило отсутствия само по себе ловушка);
   - `paid_amount` — тип «сумма» — «сколько реально пришло» — **«Если поля нет: денег ещё
     не было (или исход без оплаты)»**;
   - `reversal.amount` — одной строкой со ссылкой на `/reversal` (хозяин — Д4).
2. Добавить рабочий Mermaid **flowchart** «Как сверить оплату» (≤ 6 узлов): есть `pay_amount`?
   → сравнивай `paid_amount` с ним : сравнивай с `amount` → равно / меньше (недоплата) /
   больше (переплата) → действие словами. Существующие Steps (:58–73) остаются как текстовый
   дубль-маршрут, flowchart ставится рядом.
3. Существующий Warning (:27–32) сохранить — он и есть словесная формула ловушки.

### Д2 · Исход не вечен (хозяин `reversal.mdx`) — критичная

1. **Парадная MockFlow №1 — «Жизнь заявки после финала».** Горизонтальный таймлайн одной
   заявки: создана → PENDING → SUCCESS (✓ выдали товар) → *тишина N дней* → колбэк →
   REVERSED (деньги отозваны) → *апелляция* → колбэк → снова SUCCESS. Точки «здесь приходит
   колбэк» и подпись-мораль «слушатель не выключается никогда». Текущий Mermaid из двух
   стрелок на странице заменяется этой иллюстрацией; двухстрелочная state-схема остаётся
   рабочей на `status-stage.mdx:87–95` (там её место).
2. Карточки переходов, таблица инициаторов (:38–42), Warning (:44–46) и аккордеоны (:61–76)
   не трогать — покрытие признано полным.

## 4. Потерянные разделы спеки → куда возвращаются

Причина потери: Mintlify не рендерит `info.description`. Версионирование и трассировка уже
вернулись в `api-reference/conventions.mdx`. Оставшееся распределяется так:

### 4.1 Новая страница `reglament.mdx` — «Регламент» (вкладка Документация)

Место в навигации: группа «Как устроена заявка», после `amounts` (эту страницу — в
`docs.json` ДОБАВИТЬ, в отличие от `_design/`). Аудитория — аналитики, БЕЗ механики. Состав:

1. **Лимиты** (спека :1138–1141): частота запросов и диапазон сумм согласуются при
   подключении; при выходе за диапазон заявка не создаётся, границы в ответе не сообщаются —
   актуальные значения узнают у поддержки. Без `429`/`Retry-After` — это в conventions.
2. **Что меняется без предупреждения** (версионирование глазами аналитика, :1181–1184):
   новые необязательные поля, значения словарей (`stage`, причины), банки и платёжки
   появляются без смены версии; правило чтения — незнакомое игнорировать; ломающие изменения
   только отдельной версией, об устаревании предупреждают заранее.
3. **Как читать поля** (общие принципы, :1172–1179): даты — всегда UTC (один пример чтения
   «Z на конце — это не московское время»); суммы — числа до двух знаков; **отсутствие поля
   означает «значения нет», а не ноль** — это правило уже эксплуатируют amounts/callbacks,
   здесь его дом; словари — заглавными.
4. **Трассировка и поддержка** (:1186–1189): мини-Field/Tree трёх идентификаторов, которые
   нужно хранить и сообщать в поддержку — `transaction_id`, `occurred_at` колбэка,
   `x-request-id` («имя квитанции запроса; возвращается в каждом ответе — логируйте»).

### 4.2 Расширение `api-reference/conventions.mdx` (механика)

Дописать два раздела (сейчас страница — 1 КБ, только версии и трассировка):

## 7. Acceptance — что считается «качественно»

### Field/Tree
- У каждого поля все четыре грани: имя, тип по-русски, суть одной фразой, семантика
  отсутствия (или присутствия — для блоков). Пустая четвёртая грань = брак.
- Ноль JSON-примеров, ноль слов «string/number/object» — «строка/сумма/момент времени/блок».
- Тест: аналитик, глядя только на карточку, отвечает «в ответе нет `pay_amount` — с чем
  сверять `paid_amount`?» — не открывая спеку.

### Рабочие Mermaid
- ≤ 12 узлов; подписи по-русски; из технических терминов — только значения `status`/`stage`
  и имена полей; ноль HTTP-кодов.
- В sequence все alt-ветки подписаны исходом («оплата победила», «отмена успела»), каждая
  ветка заканчивается действием мерчанта, а не состоянием сервиса.
- Рендер без горизонтального скролла в обеих темах Mintlify (проверка на живом превью).

### Парадные схемы
- Светлая и тёмная версии; читается без легенды за 10 секунд; сюжет — одна заявка во
  времени, а не «архитектура».
- Термины — только из словарей портала; ноль выдуманных состояний.
- Файлы в `/images`, исходник в `_design/`; в тексте страницы рядом остаётся текстовый
  эквивалент (доступность + поиск).

### Правки текста (Д3, И1-психика `psp`, И4)
- grep-проверки после правки: «больше не изменится» без оговорки об апелляции — 0 вхождений;
  `psp` упомянут в «чего в колбэке нет»; «ограниченн» (время ответа на колбэк) — ≥ 1
  вхождение на `callbacks.mdx`.
- Каждый сателлит боли — ссылка на хозяина, пересказ не длиннее двух предложений.

### Регламент
- `reglament.mdx` добавлена в `docs.json` (группа «Как устроена заявка»); на странице —
  ноль HTTP-кодов и имён заголовков, кроме `x-request-id` как «имени квитанции».
- Все четыре потерянных раздела спеки находятся поиском по порталу: «лимит», «версия»,
  «UTC», «x-request-id» дают попадания на витринных страницах.
- `conventions.mdx` дополнена «Лимитами» и «Форматами»; ни один факт не живёт в двух местах
  в одинаковой формулировке (суть — Регламент, механика — conventions).

### Волна спеки
- Все 4 правки внесены; пример reversed проходит правило «pay_amount присутствует, если
  отличается от amount»; снапшот collection.json пересобран и совпадает с облаком.

## 8. Порядок исполнения

1. Текстовые правки и дыры (Д3, И1-psp, Д5, И4-п.1) — дешёвые, закрывают ложь и дыры.
2. Field/Tree (amounts → callbacks → reversal) + Mermaid (И2 sequence, И3 flowchart, Д1
   flowchart).
3. Страница «Регламент» + расширение conventions + docs.json.
4. Парадные №1 и №2; №3 — по решению владельца после приёмки.
5. Волна спеки (раздел 5) — параллельно, в aggr-contract; И4-п.2 — после её п. 4.
